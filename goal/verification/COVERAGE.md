# Verification coverage inventory

This is the reviewed inventory of production behavior. `coverage.json` is checked against every production module, model/configuration and bounded implementation group. It prevents unlisted files and missing references; it cannot automatically discover every property inside an existing function. Changes require human review of this inventory.

AutoClearProtocol enumerates five prior goal statuses, audit-pass/unfinished-queue/pending-charge Booleans, and one user or extension input. It checks verified completion, real input, queue preservation, final charging and continued message delivery before cleanup. Other models and runtime/SDK regressions cover identity, ownership, history and complete audit transitions; there is no composition proof.

ContextProtocol now uses two projection steps and a 0–2 policy-copy count. The accumulation control violates SinglePolicy; actual old-message removal, queue reconstruction and post-compaction policy injection are covered by implementation/SDK tests. Eligibility is abstracted as owned live work in the fixed message corpus; there is no model of provider prompt understanding.

VerificationProtocol uses two environment identities (declared snapshot vs. sandbox used), phases idle/running/active/paused/passed, 0–2 consecutive environment failures and up to two repairs. It checks that each run uses the submitted snapshot, environment-classified failures never consume an implementation repair, never complete a goal, and stop after two consecutive environment failures unless the environment is adjusted. Runtime tests connect this to sandbox composition, submit classification and `goal_environment`; actual microVM/network enforcement is covered by the separately invoked acceptance suite.

Models are separate manual abstractions without a composition/refinement theorem. Bounded implementation enumeration executes actual TypeScript with independent expected outcomes over the domains recorded in `results/contracts.json`; it is exhaustive testing within those finite domains, not an unbounded theorem. The Java/Node runtimes, TLA+/TLC, TypeScript stripping, cryptography and this verification infrastructure are trusted, with runner regression tests.

Permission uses two exact request keys and at most three confirmation epochs. Accounting uses four worker turns, two known audit charges, two resumes and a reduced stagnation threshold of three; the implementation enumeration uses counters through six, including the production thresholds. Recovery abstracts validation to a Boolean, owner session to 1/2, two appends and atomic installation under both locks; it does not model physical disk bytes. Storage contracts enumerate diff/apply round-trips, append-only evidence, removals and invalid patches; they do not model concurrent writers, filesystem durability or arbitrary JSON. Context enumerates two sessions/goals/generations and projects a fixed corpus. Inspection allows two responses and findings over two required IDs plus one foreign ID. Check uses two identities and one child execution; Verification adds two environment identities, a 0–2 failure counter and one snapshot per run. Scheduling uses two continuation boundaries with symbolic pending input/outcome/gates and final usage settlement. Increasing these domains is a new verification run, not an inference from this one.
