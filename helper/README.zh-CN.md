# my-pi-helper

为 Pi 提供按请求调用的独立助手。主会话明确提供任务和材料，Helper 使用允许的工具处理任务，然后返回结果。每次调用都创建新的上下文。

[English](README.md) · [设计与边界](DESIGN.md)

## 安装

要求 Node.js **22.19+**，支持 Pi **1.3.0 / 1.4.0**。三个包独立维护，Helper 不依赖 CodeGraph 或 Search，也不需要额外的 subagent 插件。

在仓库根目录执行：

```bash
pi install ./helper
```

仅为当前项目安装，可使用 `pi install -l /absolute/path/my-pi-tools/helper`。临时加载、不修改配置：

```bash
pi -e /absolute/path/my-pi-tools/helper/extensions/index.ts
```

此包未发布到 npm，请从本地路径安装。安装或更新扩展后，在运行中的 Pi 执行 `/reload`，或启动新的 Pi 会话。

## 调用方式

主模型直接调用 `helper`。这是 `model-only` 工具，不能由 codemode、其他工具或 Helper 自己递归调用。

默认只读：

```json
{
  "task": "检查 src/export.ts 中 Unicode 文件名的处理，指出具体问题和位置。",
  "context": "预期行为：下载的归档应保留 Unicode 文件名。请独立检查，不修改文件。"
}
```

明确允许执行：

```json
{
  "mode": "work",
  "task": "修复 src/export.ts 的 Unicode 文件名问题，并运行相关测试。",
  "context": "保持公共 API 不变。遵守项目格式要求。测试位于 test/export.test.ts。返回修改文件、检查结果和未解决问题。"
}
```

| 参数 | 含义 |
| --- | --- |
| `task` | 必填，非空任务，最多 20,000 字符 |
| `context` | 可选，补充材料和约束，最多 120,000 字符 |
| `mode` | 默认 `read`；显式指定 `work` 才开放写入和命令执行 |

Helper 不继承主会话的消息、系统提示、推理、压缩摘要或之前的 Helper 对话。请明确提供相关路径、项目规则、验收要求和追问所需的已有结果。它可以在本次调用内保留自己的工具结果；调用结束后丢弃对话。信息不足时会返回问题或限制说明，由主会话决定是否再次调用。

## 工具范围

| 模式 | 可选工具 |
| --- | --- |
| `read` | `read`、`grep`、`find`、`ls` |
| `work` | 只读工具加 `write`、`edit`、`bash`、`powershell` |

实际工具集取上述名单与宿主当前可调用工具的交集。Helper 不会启用被关闭的工具。Pi 默认工具集下，只读模式可能只有 `read`；此时需要主会话提供具体文件路径，或在宿主中启用 `grep`、`find`、`ls`。

所有工具调用都经过宿主验证和权限钩子。钩子改写参数时，观察到的实际参数会反馈给 Helper。工具失败或被拒绝后，本次调用立即返回错误及最后一次工具输出；宿主要求终止时，终止信号也会传回主会话。

工作模式已经完成的修改保留在共享工作区中，不自动回滚。上下文独立不等于文件系统隔离，也不提供操作系统沙箱。宿主工具及其替换实现属于可信基础。

## 返回结果与结束行为

结果包含 `status`、`output`、`reason`、`partial`、模型、模式、轮次、工具调用数、用量和截断标记，非正常结束且工具已经返回时，还会包含 `lastTool` 输出；正常回答不附带原始工具输出，避免将读过的文件再次灌入主会话上下文。

| 状态 | 含义 |
| --- | --- |
| `answered` | 模型给出了普通最终回答，也可能是在说明缺少的信息 |
| `error` | 模型或工具失败、调用被拒绝、参数无效，或返回了不支持的非文本内容 |
| `cancelled` | 调用或会话取消、运行时关闭，或模型中止 |
| `limited` | 达到轮次、工具调用数、时间、上下文或输出限制 |
| `terminated` | 宿主工具要求终止 |

无效的调用参数或配置可能在产生 Helper 结果前被拒绝，此时 Pi 会返回普通工具错误。

`answered` 只表示返回了模型回答，不代表整个用户任务已经独立验收。其他状态会设置 `partial: true`，并尽可能保留最后一段非空模型输出和最后一次工具结果。

`usage` 是 Helper 模型调用的用量；嵌套工具的用量由 Pi 另行汇总。缺失或无效的用量标记为 `usageIncomplete`；缺失汇总字段时，使用已知分项计算部分总数，并防止数值溢出。`reasoning` 和 `cacheWrite1h` 按已报告的值累计，它们是既有 token 数量的子集，不重复增加总量或费用。轮次只统计已开始的模型请求，不计入进度回调中取消的请求。

模型返回普通最终回答后，本次调用即结束。信息不足时会向主会话说明，主会话可以在新请求中补充材料。Helper 不自动重试或恢复主会话执行，每次调用都有独立的对话。

最后一个允许的模型轮次若仍要求调用工具，会返回限制结果，不再执行无法继续查看结果的动作。整批工具会在任何动作前完成校验，包括 SDK 的 JSON 参数解析错误以及缺失、无效或重复的调用 ID。工具额度用完后，只要模型轮次、时间和上下文仍有余额，就允许模型读取最后的结果并回答；任何新的工具批次都会被拒绝。

## 配置

依次读取 `<Pi agent 目录>/my-pi-helper.json` 与 `<工作区>/.pi/my-pi-helper.json`，项目配置覆盖个人配置：

```json
{
  "maxTurns": 20,
  "maxToolCalls": 200,
  "timeoutSeconds": 1200,
  "maxContextChars": 200000
}
```

| 配置项 | 默认值 | 允许范围 |
| --- | --- | --- |
| `maxTurns` | 20 | 1–200 轮模型请求 |
| `maxToolCalls` | 200 | 1–1,000 次工具调用 |
| `timeoutSeconds` | 1,200 | 1–3,600 秒 |
| `maxContextChars` | 200,000 | 1,000–2,000,000 字符 |

上下文字符数包含工具定义，不是精确 token 或费用预算。

每轮模型请求直接使用所选模型自身的输出上限（`model.maxTokens`）。最终返回回答的 32,000 字符限制仍然保留。

可同时设置 `provider` 和 `model` 选择其他已配置模型；不设置则复用当前模型的标识与认证。`thinking` 可设为 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`，默认使用当前思考等级。这些配置复用不会带入主会话对话内容。

非法配置、未知字段和不完整的模型配置会报错。工具输出摘录和回答最多 32,000 字符，并明确标记截断；需要更多内容时应缩小任务或分段读取。Helper 支持文本、前台调用和每次全新上下文。

超时和取消使用协作式中止信号，依赖宿主工具与 provider 响应，不负责强制杀死任意扩展代码。操作之间也会检查单调时钟，确保同步工具阻塞计时器后，不会在已经超时的情况下继续启动后续动作。

## 验证

```bash
npm --prefix helper ci --ignore-scripts
npm --prefix helper run check
npm --prefix helper test
npm --prefix helper run check:format
npm --prefix helper run check:compat
```

双版本检查默认使用 `~/.pi/agent/install/releases` 下的 Pi 1.3.0 / 1.4.0，在临时副本中检查类型、完整测试和扩展加载，不重连或改写正在使用的安装。

测试通过离线 provider 和真实 Pi SDK 验证上下文边界、文件修改、命令执行、权限拒绝与改写、终止、取消和有限执行。CI 配置覆盖 Node 22 / 24 与两个 Pi 版本。这些检查覆盖运行行为和集成，不评估模型回答质量，也不提供形式化证明。
